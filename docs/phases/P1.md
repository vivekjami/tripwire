## 2. What Phase 1 is for

Build a secure, observable, correct pass-through gateway that already parses OpenAI traffic with the production scanner and SSE codec, **with no detectors yet**. The point is to measure the cost of parsing in isolation, so that when detection arrives in Phase 2 its cost can be separated from the plumbing.

## 3. What was built, work package by work package

### WP1.1 Edge and lifecycle (`internal/config`, `internal/gateway`, `cmd/tripwire`)
- **Strict config.** Unknown fields are errors; every validation error carries the YAML line; defaults are the architecture's limits; a JSON Schema is generated from the structs (`docs/config.schema.json`), and a test fails if it goes stale (it caught me forgetting to regenerate it twice).
- **Listeners and limits.** Separate data and admin listeners (the admin plane is never on the data port), HTTP/1.1, optional cleartext HTTP/2, TLS with **hot-reloading certificates** (a bad replacement keeps the old one serving), header/idle/read-header/body/connection limits.
- **Lifecycle.** SIGTERM flips readiness first, lets in-flight requests and streams finish, then closes stragglers at `drain_timeout`. SIGHUP swaps the agent registry; a bad file keeps the old one. Panics return 500 without the panic text and the server survives (fail closed).
- **Why:** an edge that is wrong or that falls over under reload makes every later measurement meaningless, and the hardening list in ARCHITECTURE §14 is a requirement, not polish.

### WP1.2 Authentication, registry, limits (`internal/auth`)
- **API keys** `tw_<agent>_<43 chars>`: stored only as SHA-256(pepper ∥ key), constant-time compare, rotation overlap windows, duplicate `Authorization` headers rejected.
- **JWT** (EdDSA / ES256 / RS256): the algorithm allow-list comes from configuration, never from the token, and the key's type must equal the algorithm, so `none`, every HMAC algorithm and RS256↔HS256 confusion cannot be expressed. JWKS cache with refresh, rate-limited refresh on unknown `kid`, **stale-if-error** up to `stale_max`, RSA < 2048 bits ignored. Verified tokens are cached by hash for at most 5 minutes so a revoked key is honoured promptly.
- **mTLS**: a verified client certificate's URI SAN maps to an agent; a presented certificate must chain to the configured CA; if a certificate and a bearer token are both sent they must name the same agent.
- **Admission control:** immutable registry snapshot (`atomic.Pointer`), per-agent GCRA rate limit (one atomic), per-agent concurrent-stream cap, global in-flight cap with 429 + `Retry-After`. Limiter state survives a reload that did not change the agent's limits.
- **Uniform failures.** Every authentication failure returns identical status, headers and body. For JWTs, pre-signature failures run a dummy verification; measured median failure latency across six failure classes is within 1.6× (`TestJWTFailureTimingIsUniform`).

### WP1.3 Router and non-stream chat (`internal/openai`, `internal/upstream`, `internal/jsonscan` v1)
- **Strict JSON scanner v1:** rejects duplicate keys (compared *after* decoding escapes), invalid UTF-8, unescaped control characters, lone surrogate escapes, BOM, trailing data, bad number grammar, numbers that overflow float64, and anything beyond the depth/size/key/string limits. The point: the gateway forwards **only bytes it has validated**, so two parsers cannot disagree about what was sent (ADR-27).
- **Role-aware field walker** (`openai.Walker`), the hook where detectors attach in Phase 2; a no-op in Phase 1.
- **Upstream client with credential brokering:** the agent's credential is deleted after authentication and never forwarded; outbound headers are built from an allow-list (never copied); the upstream credential is injected; `Accept-Encoding: identity`; `traceparent` propagated only if well-formed; no environment proxy; request path validated.
- **Request hardening:** `Content-Type` must be `application/json`, gzip bodies are bounded by size *and* decompression ratio, unknown encodings are refused, the model must exist *and* be in the agent's scope with **identical** responses for "does not exist" and "not allowed to you".
- **Retries only when the request provably never reached the upstream** (dial failures); never for a POST that may have been processed.
- **Response handling:** bounded read, JSON validated, upstream 401/403 mapped to 502 (the gateway's credential failing must not look like the agent's), non-JSON and malformed bodies rejected, Content-Length recomputed from the bytes actually sent.
- **Models list** is the union of upstream lists filtered to routed models in the agent's scope.

### WP1.4 SSE codec and streaming passthrough (`internal/sse`, `internal/gateway/stream.go`)
- **Incremental decoder:** line endings CRLF/LF/CR, BOM only at stream start, comments, multi-line data, event/size limits; events point into a reused window (**0 allocations**, 384 MB/s on this host), and the exact original bytes of every event are kept so unmodified events are forwarded **verbatim**.
- **Streaming loop** (one read-inspect-write loop per stream, ADR-18): headers flush on the first upstream byte; write deadlines; idle, byte, event-size and duration caps; client disconnect cancels the upstream (no tokens paid for nobody); malformed upstream events end the stream with an error event and `[DONE]` (ADR-26); per-agent concurrent-stream cap.
- **Read coalescing:** all events already received are written together and flushed once when no complete event remains buffered. No event waits for data that has not arrived; a burst costs one syscall instead of N (found by profiling, §6).

### WP1.5 Streaming scanner and splice API (`internal/jsonscan` v2)
- Same strict rules, but **zero allocations** in steady state (reusable key stacks), plus a **locator** for `choices[*].delta|message.{content, refusal, content-parts text, tool_calls[*].function.{name,arguments}, function_call}` that never confuses look-alike paths.
- **Resumable `Unescaper`:** decodes JSON string bodies across calls, rejoining a surrogate pair whose halves arrive in different events, and handling split escapes and split UTF-8.
- **Position map and `Splice`:** map a range of decoded text back to raw bytes and replace it, copying every other byte untouched (the basis of rewriting in Phase 2).
- Throughput **≈ 308 MB/s, 0 allocs/op** against the 500 MB/s hypothesis (a miss on this host; AMD-022).

### WP1.6 Lineage skeleton and the ClickHouse probe (`internal/lineage`, `deploy/ch`, `cmd/twmigrate`, `twload -mode lineage`)
- **Pipeline:** pooled event structs, a lock-free MPSC ring, batching writers, sinks (null, memory, ClickHouse). `Emit` **never blocks** the request path: a full ring drops and counts. A wedged sink was shown not to slow requests.
- **DDL v1** (all four tables) with a test that the Go structs and the DDL list the same columns in the same order, and that no table has a column that could hold a raw value. Time-ordered 64-bit ids (41-bit ms | 10-bit node | 12-bit sequence).
- **ClickHouse sink and migration runner** (`ch-go` native column blocks, deduplication token per block, checksum-locked migrations). **Compile-checked only; never run against a server.**
- **Probe tool:** `twload run -mode lineage` drives the real pipeline at a target rate and reports emitted/dropped/committed/failed, enqueue p99, ring depth and CPU.

### WP1.7 Request events and stage timing
- Per-request state in the request context; one `request_events` row per **authenticated** request with sizes, counts and stage timings (authn, scan, upstream wait, time added by the gateway); `Server-Timing` only for agents flagged `admin`. A test confirms events never contain payload text.

## 4. Defects the work found (value of testing as we went)

| # | Found by | Defect | Fix |
|---|---|---|---|
| 1 | differential fuzz vs `encoding/json` (within a minute) | `1e1000` is valid JSON grammar but means infinity in other parsers | reject numbers that overflow float64 (AMD-018) |
| 2 | differential fuzz of the SSE decoder vs a slow reference | a BOM-looking sequence after a stray blank line was stripped when the first read was small | BOM only at the absolute stream start |
| 3 | security test (raw sockets) | Go's parser accepts `Transfer-Encoding: chunked` with `Content-Length` and deletes the length before handlers run, so the combination reached the upstream | the data plane refuses any `Transfer-Encoding` (AMD-017) |
| 4 | race detector | the queue-depth gauge read the ring consumer's plain cursor | made it atomic |
| 5 | code review of my own change | the bearer token would have been written into `config.json` in the committed results | blanked before writing; regression test |
| 6 | `staticcheck` on Go 1.26 | deprecated `ecdsa.PublicKey.X/Y` | `ParseUncompressedPublicKey` (also validates the curve point) |
| 7 | allocation test | measured 1 alloc/event: my fake upstream, not the gateway (net/http boxes chunk lengths ≥ 256 B) | isolate the gateway's per-event path in `TestPumpPerEventPathDoesNotAllocate` |
| 8 | profiling vs the null proxy | one flush syscall per event instead of one per burst | read coalescing |
| 9 | my own tests | several wrong expectations (line numbers, mTLS untrusted-CA behaviour, fuzz fixtures) | fixed in the test, never by loosening the product |

## 5. Security evidence

Header-leak (agent credential, cookies, `X-Forwarded-*`, `Proxy-Authorization` never reach the upstream; upstream headers never reach the client); smuggling suite (CL+TE, TE+CL, duplicate differing CL, obs-fold, bare LF, obfuscated TE, space before colon: nothing is ever executed, forwarded or authenticated); oversize and gzip-bomb (size cap and ratio cap); alg-confusion (HS256 with the RSA modulus or `kid` as key, `none`, key-type mismatch, tampered payload, stripped signature, duplicate keys in header/payload, unknown `kid`, expired, not-yet-valid, wrong issuer/audience, missing `exp`); limit tests (header size, body size, connections, concurrent streams, in-flight, rate); uniform-failure tests for both API keys and JWTs; fail-closed on panic; credential never in results.

## 6. Performance (shape-only: this is a virtualised WSL2 host; 0 of 66+ session runs are `valid`)

Procedure: `scripts/rig-local-gateway.sh`; floor = null proxy, gateway = auth + strict parse + SSE decode + delta scan + request events, no detectors; same 2 pinned cores; 64 events/response at 5 ms gaps; analysis in `bench/sessions/p1-synth-20261124*/analysis.md`.

| Measurement | Result |
|---|---|
| Added p99 per-event latency over the null proxy at 70 % of knee | **0.3 ms** (first session, 5 runs pooled); later sessions' p99 is dominated by host noise (the null proxy's own p99 varied 1.0–3.2 ms between sessions). Criterion ≤ 1 ms: **met**. p50 added: 19–44 µs. |
| CPU per request, gateway vs null proxy at ~200 req/s | ×1.18 before optimisation, **×1.13** after, **+10 %** in the final fine sweep (0.76 vs 0.69 cores) |
| Knee (merged event p99 ≤ 5 ms, ≥ 98 % achieved) | coarse sweep: null 300, gateway 200 req/s. **Fine sweep (25 req/s steps, 4 runs): null 225, gateway 200 = 89 %.** Criterion ≥ 90 %: **marginal miss**, inside the sweep resolution, not a pass. |
| Allocations per event | gateway's own path **≈ 0.0001 allocs/event** (three read-burst shapes); end to end 0.007–0.26/event, the rest being `net/http`'s chunk writer (one boxed length per flush ≥ 256 B) |
| Goroutines and file descriptors after 200 streams (half aborted) | flat (`TestNoGoroutineOrFDLeakAfterChurn`) |
| HTTP/2 stress | 400 concurrent streams over 4 h2c connections: all complete, in order, no starvation (`TestH2ManyConcurrentStreams`) |
| Scanner / decoder | 308 MB/s and 384 MB/s, both 0 allocs/op (AMD-022 records the scanner's miss against the 500 MB/s hypothesis) |

What the optimisation work established: the profile attributed the extra cost to syscalls, because the null proxy writes once per upstream *read* while the gateway wrote once per *event*. Read coalescing, amortised write-deadline re-arming and batched counters brought CPU from ×1.18 to about ×1.10. Without a real rig, "+10 % CPU" cannot be separated from noise with confidence, so the knee criterion is recorded as not demonstrated.

## 7. Lineage ingest probe: what exists and what does not

- **Measured:** the pipeline alone (ring, batcher, writers, null sink) sustained **1 000 000 events/s for 15 s with 0 drops and 0 failures**, enqueue p99 450 ns, ring max depth 3 578 of 262 144 (`bench/results/p1-lineage-null-1M`). Shape-only: shared host, producers included in the CPU figure.
- **Not measured:** the ClickHouse ceiling, part counts, merge pressure and the settings that matter. No ClickHouse server was available in this environment (an attempt to download one was blocked), so `CHSink` and `Migrate` have never talked to a server. **The plan's rule applies: until this runs, the 1 M rows/s claim for ClickHouse is unproven.** `bench/RUNBOOK.md` has the exact procedure.

## 11. Retro

- **Estimate vs actual:** ≈ 40 h estimated; actual not tracked. Scope exceeded the plan in places (HTTP/2 stress test, JWKS stale-if-error, mTLS, differential fuzzers, probe tool) because the tests that found real defects were worth more than the schedule saved.
- **Surprises:** the differential and race tools earned their keep (defects 1, 2, 4); the profile contradicted my first guess about where the extra CPU went; the standard library has its own per-flush allocation that a naïve "0 allocs" gate would have blamed on us.
- **What I would not claim:** that the gateway meets the 90 % knee criterion, that ClickHouse sustains 1 M rows/s, or any figure from this host as a published number.
