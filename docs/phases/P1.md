# Phase 1: Core proxy and stream plumbing (brief and status)

Plan reference: [IMPLEMENTATION_PLAN §5](../IMPLEMENTATION_PLAN.md#5-phase-1--core-proxy-and-stream-plumbing). Estimate ≈ 40 h. **Status: in progress. 2 of 7 work packages are partly done; nothing here has been measured on a real rig.**

## Objective
A secure, observable, correct *pass-through-with-parsing* gateway: authenticates, routes, parses OpenAI traffic with the production JSON scanner and SSE codec, enforces limits, forwards, emits request events, **with no detectors yet**, so parsing cost is measured in isolation above the Phase 0 null-proxy floor.

### WP1.1 delivered
- `internal/config`: strict YAML (unknown fields rejected), explicit defaults from ARCHITECTURE §14.2, **every validation error carries its YAML line**, JSON Schema generated from the structs (`docs/config.schema.json`, kept in sync by a test and `make schema`), fuzzed (`FuzzParse`).
- `internal/gateway`: data and admin listeners (admin never on the data port), h1, optional h2c, TLS with **hot-reloading certificates** (a bad replacement keeps the old one serving), header/idle/read-header limits, per-agent and global body limits, optional connection cap, **graceful drain** on SIGTERM (readiness flips first, in-flight requests finish, `drain_timeout` closes stragglers), SIGHUP registry reload (a bad file keeps the old registry), startup banner (version, revision, Go version, GOMAXPROCS), `GOMAXPROCS`/memory-limit handling, panic recovery that **fails closed** (500, no panic text).
- `cmd/tripwire`: `-config`, `-check`, `-print-schema`, `genkey`.

### WP1.2 delivered
- `internal/auth`: API keys `tw_<agent>_<43 base64url>`, stored as SHA-256(pepper ∥ key), constant-time compare, **uniform failure** (malformed, unknown agent, expired and wrong keys all do the same work and return the same bytes), rotation overlap windows (`not_before`/`not_after`), duplicate `Authorization` headers rejected.
- Registry as an immutable `atomic.Pointer` snapshot; limiter state survives a reload that did not change an agent's limits; glob matching with exact semantics (no normalization; `?` is literal).
- GCRA token bucket (one atomic per agent), concurrent-stream gate, global in-flight shedding with `429` + `Retry-After`.
- Inbound `Authorization` is deleted after authentication so no later stage can forward it.

## Tests (all passing locally with `-race`)
Uniform auth failures; credential stripped; admin plane separate; rate limit; global shed; panic fails closed and the server survives; body limit; header limit; stream cap; graceful drain; drain timeout; h2c on/off; connection cap; TLS reload (good, bad, ALPN h2); config reload; registry reload under load; rotation windows.

## Metric names introduced (frozen at the end of Phase 1; dashboards depend on them)
`tw_http_requests_total{class}`, `tw_http_request_seconds` (native histogram), `tw_inflight_requests`, `tw_shed_total{reason}`, `tw_auth_failures_total`, `tw_panics_total`, `tw_tls_reload_total{result}`, `tw_registry_reload_total{result}`, `tw_registry_agents`.

## Exit criteria (all open)
Compatibility with official SDKs; security tests (header-leak, smuggling, oversize/bomb, alg-confusion); fuzz targets ≥ 10 min each; parse-only performance ≥ 90 % of the null-proxy knee with p99 added ≤ 1 ms [hypothesis]; lineage ingest probe; frozen metric names, config v0.9, lineage DDL v1.

## Honest caveats
- **Performance criteria cannot be met here.** They are defined against a real rig; this host's runs are shape-only (Phase 0). Parse-only overhead will be reported as a ratio against the null proxy on the same host, labelled shape-only, until a real rig exists.
- The Python/TypeScript SDK compatibility matrix needs those SDKs installed; not checked yet.
- ClickHouse probe needs a ClickHouse server; none is available on this machine.
