# Phase 0: Foundations and the measurement harness

Plan reference: [IMPLEMENTATION_PLAN §4](../IMPLEMENTATION_PLAN.md#4-phase-0--foundations-and-the-measurement-harness). Estimate: ≈ 28 h (actual hours were not tracked).

Written for: the project owner and future contributors who need to know exactly what Phase 0 delivered, why each piece exists, how far to trust it, and how to reproduce it.

## 1. Verdict, stated plainly

**Phase 0 is complete on a synthetic rig.** Every deliverable in the plan exists, is tested, and was exercised end to end. Every exit criterion has an answer.

Three things are *not* true, and nothing in this repository should be read as claiming them:

1. **No number here is a publishable measurement.** Every one of the 53 session runs, and the 4 earlier laptop runs, is flagged `valid=false`. The host is a WSL2 virtual machine whose timers overshoot by about 1 ms, so the load generator cannot meet the plan's dispatch-lag bound (p99 < 200 µs). The plan says such runs are discarded, and they are: they show *shape* only.
2. **The R1 decision and the transport/TLS decision are provisional** ([AMD-013](../adr/AMENDMENTS.md), [AMD-014](../adr/AMENDMENTS.md)). They were made from shape-only data because the plan needs a default now. The first real-rig session must confirm or reverse them before Phase 5 sizing.
3. **Several inputs are unverified**: the MCP and OpenAI spec notes (no web access), the real BurstGPT trace (never fetched, so a synthetic one stands in), the GitHub-hosted CI run (pushed, but I did not observe it), and the Docker Compose stack (no Docker on this machine).

## 2. Why Phase 0 exists

Tripwire's headline claim is "under 10 ms p99 added latency at 20 000 requests/s while redacting secrets in streams". A claim like that is only as good as the instrument that measures it. The plan therefore builds the instrument *first*, and proves the instrument is honest, before any gateway code exists. Concretely Phase 0 has to answer:

- Can we generate load that does not lie? (Closed-loop generators hide stalls; this is "coordinated omission".)
- Can we tell, per streamed event, how long the gateway held it? (Needs timestamps from both ends of the pipe on one clock.)
- Can we tell whether redaction *worked*? (Needs ground truth: we must know exactly which fake secrets we injected and where.)
- What is the floor? (A proxy that does nothing sets the minimum added latency and CPU; the gateway's real cost is measured on top of it.)
- Is the planned rig big enough for 20 K req/s? (Requires a fitted cost model, risk R1 in the plan.)

## 3. What was built, and the reason for each piece

All Go, module `github.com/vivekjami/tripwire`, Go 1.26.11, `CGO_ENABLED=0`. About 7 500 lines of Go including tests.

### 3.1 Foundation packages (`internal/`)

| Package | What it does | Why |
|---|---|---|
| `clock` | Reads `CLOCK_MONOTONIC` via `x/sys/unix`. | The mock stamps when it *emitted* an event and the load generator stamps when it *received* it, in different processes. Only a shared monotonic clock makes the difference meaningful. Wall-clock time can jump. |
| `sysutil` | Raises `RLIMIT_NOFILE`; reads process CPU seconds. | 20 K req/s means tens of thousands of sockets; CPU seconds feed the capacity model. |
| `validate` | Luhn check. | Generated card numbers must be valid PANs, otherwise a detector could rightly ignore them. |
| `gen` | Generators for card numbers (PAN), AWS keys, GitHub tokens, emails; a strict loader for `eval/classes.yaml` (27 data classes). | The injected "secrets" must be realistic in shape but fake, and every class the gateway will detect needs one registry that tests and the evaluation share. The loader rejects unknown fields so the registry cannot silently drift. |
| `groundtruth` | Records of injected spans (class, value, normalized form, hash, offset, length) and per-stream event boundaries; `Check` (leak and alteration verdicts); a JSON-string decoder that preserves lone UTF-16 surrogates; emit-timestamp log; `Sampled`. | This is what turns "0 leaks" from a hope into a measurement. The surrogate-preserving decoder matters because a stream can split an emoji across two events; a normal decoder would corrupt the value and hide a leak. |
| `hist` | A sharded HdrHistogram recorder, `Summarize`, `Save`, `Load`. | Thousands of goroutines record latencies; one mutex would distort what is measured. Percentiles are only ever computed on a *merged* histogram, never averaged (averaging percentiles is mathematically wrong and is a classic benchmark error). |
| `trace` | Poisson arrivals and a BurstGPT CSV loader that rescales to a target mean rate. | Real traffic is bursty; a homogeneous Poisson stream understates tails. The loader refuses a header it does not recognise rather than guessing, because the true schema was never verified. |
| `envinfo` | Captures host, kernel, CPU, governor, sysctls, Go version and git state into `env.json`; no hostname; home paths scrubbed (AMD-009); stamps WSL2 as "shape-only". | Plan rule: every number must be traceable to the exact machine and commit. Result directories are committed and may be public, hence no hostname or home path. |
| `obs` | Metrics registry, admin handler (`/metrics`, pprof), allow-listed `slog` logger, no-op OpenTelemetry tracer, a request-event record, a zero-allocation stage timer. | The gateway will be measured by its own metrics, so the baseline observability is built and tested before the gateway. The logger only accepts allow-listed fields so a secret can never be logged by accident. |

### 3.2 The mock upstream (`internal/mock`, `cmd/twmock`)

A fake LLM and MCP server whose behaviour is fully controlled and fully recorded.

- **Surfaces:** OpenAI Chat Completions (stream and non-stream), a subset of the Responses API, and MCP tool calls (including a "hostile" mode with malformed or adversarial results).
- **Text and chunking:** benign text from an authored word list (AMD-002) with injected fake secrets; chunking modes `token`, `per-char`, `random:P`, `boundary` (splits exactly at a secret's edge) and `adversarial`. Every mode is tested to reassemble to the original text.
- **Timing:** a configurable inter-event gap; emission to an *absolute* schedule so jitter does not accumulate (AMD-008); the true emit time of each event is stamped and logged for a sampled subset of streams.
- **Faults:** reset, stall, truncation and similar, plus `/_tw/stall`, `/_tw/flush` and `/_tw/stats` control endpoints.
- **Control channel:** the body field `metadata.tw_mock`, not headers (AMD-001), because the gateway strips non-allow-listed headers and a header-driven mock would silently fall back to defaults while a test still appeared to pass.

### 3.3 The load generator (`internal/load`, `cmd/twload`)

- **Open loop.** Arrivals follow a schedule (Poisson, or a replayed trace). A request is sent at its scheduled time whether or not earlier requests have finished, and latency is measured **from the intended send time**. This is what defeats coordinated omission: when the system stalls, the queue of late requests shows up as latency instead of being hidden by a generator that politely waits.
- **Spin-margin dispatch** (AMD-006). Go timers wake late (about 1 ms here), so the dispatcher sleeps for most of a gap and busy-waits the last stretch. It costs a core and is counted in generator CPU.
- **Run validity.** A run is flagged invalid if generator CPU > 60 %, dispatch-lag p99 > 200 µs (both from the plan), or any scheduled arrival was never sent (AMD-007, my addition). Invalid runs are kept for diagnosis but never cited.
- **Per-event join.** For a sampled subset of streams the generator's receive timestamp is joined to the mock's emit timestamp, giving "event delay" per event across two processes.
- **Ground-truth check.** For sampled streams it parses the stream, reconstructs the text, and reports leaked spans, altered benign streams, parse errors and incomplete streams.
- **Other modes:** MCP, an idle-connection storm, h2c, and (added in the synthetic-rig step) TLS with `-tls-ca` and `-h2`. Certificate verification is never skippable; a test proves an untrusted certificate fails.
- **Subcommands:** `run`, `diff` (percentile-wise added latency between two runs) and `timer` (measures sleep overshoot so the spin margin can be chosen).

### 3.4 The null proxy (`internal/nullproxy`, `cmd/twnull`)

A pass-through reverse proxy that does nothing except forward. It defines the **floor**: the cost of just moving bytes. Whatever Tripwire later adds on top is its inspection cost, measured against this floor. It buffers the (bounded) request body (AMD-005), refuses any request line that is not origin-form (so it can never act as an open proxy), has per-kind error counters, and supports multiple upstream ports, h2c in both directions, and TLS downstream.

### 3.5 Analysis tools

- `twfit`: ordinary least squares for `cores = R·c_r + E·c_e`, where R is requests/s and E is events/s. It refuses collinear input, because if events per response never varies independently of rate the two costs cannot be separated.
- `twagg` (new): groups repeated runs of one point, merges their histograms, and reports the across-run mean of per-run p99 with a 95 % Student-t confidence interval. The merged percentile answers "what is the latency distribution"; the CI answers "would I get the same p99 next time".
- `twcanary` (new): fixed CPU loop plus loopback ping-pong; a host more than 5 % off its stored baseline is too noisy to benchmark.
- `twtrace` (new): writes a *synthetic* BurstGPT-shaped trace (see 6.4).

### 3.6 Repository, CI and operations

Makefile, Dockerfile, `.golangci.yml`, GitHub Actions workflow, PR template, `docs/CONVENTIONS.md`, ADR template, and an amendment log (AMD-001…014). Scripts: `bench-quick.sh` (60 s single-box sanity run), `fuzz-smoke.sh`, `escape-check.sh` (heap-escape gate, no hot packages yet). Rig tooling: `deploy/rig/` (BYO-host scripts, host setup, sysctl profile), `bench/RUNBOOK.md`, `COSTS.md`, compose stack, Prometheus config, Grafana dashboard.

## 4. How the harness proves it is honest (self-validation)

The plan requires the instrument to be tested before it is trusted. Results on this host (WSL2, 8 vCPU):

| Check | Threshold | Result | Status |
|---|---|---|---|
| Coordinated omission: inject a 500 ms stall at t = 1 s at 1 000 req/s | open-loop p99 must show the stall; a closed-loop control must hide it | open p99 **474 ms**; closed-loop p99 **325 µs** | **pass** |
| Generator headroom at 10 K req/s (rig: 30 K) | CPU < 60 %, dispatch-lag p99 < 200 µs | CPU 33 % (pass); lag p99 **1.25 ms** | **fails strict** (host timers) |
| Cross-process clock join with 2 ms injected delay | recovered within ±50 µs | off by 55 and 77 µs | **fails strict by a small margin** (host timers) |
| Mock emission jitter at ≈ 200 streams | bounded (no plan number) | p50 454 µs, p99 1.8 ms | recorded (AMD-008) |

`twload timer` shows the cause: sleep overshoot of ≈ 1.2 ms for sub-millisecond sleeps. I did **not** loosen any threshold. `make selfcheck` stays strict and must pass on real hardware; `make selfcheck-laptop` merely logs the two timer-bound checks so development can continue. The same four checks were re-run in strict mode as pre-flight of the synthetic session (same two failures).

## 5. Problems the harness found in itself (the point of doing Phase 0 first)

1. **Biased sampling (AMD-011).** A requested 10 % stream sample came out anywhere from 5 % to 35 %, depending on the run-id prefix, because FNV-1a high bits are poorly distributed for ids like `<run>-<n>`. Spotted because joined-event counts did not scale with the sample fraction. Fixed with a murmur3 finalizer; a regression test fails on the old hash. The first batch of local results was discarded and regenerated.
2. **Proxy truncating streams (AMD-005).** Handing the inbound request body to the outbound transport truncated about 0.5 % of long concurrent streams. Found through `twload`'s `stream_truncated` error accounting; fixed by buffering the bounded request body; regression-tested.
3. **Generator silently under-offering (AMD-007).** A generator pinned behind schedule kept working through its backlog and reported a calm run. Now the window is hard-bounded and unsent arrivals invalidate the run.
4. **Timer resolution (AMD-006).** Forced the spin-margin design and the `twload timer` pre-flight.
5. **Vulnerable toolchain (AMD-003).** `govulncheck` reported 29 standard-library vulnerabilities in Go 1.26.0; pinned 1.26.11.
6. **Deprecated HTTP/2 packages (AMD-004).** `staticcheck` flagged `x/net/http2`; migrated to the standard library's `http.Protocols`.
7. **Open-proxy behaviour.** A linter's SSRF finding led to a test showing the null proxy would forward an absolute-form request line (`GET http://evil.example/x`) to its upstream. It now returns 400; `TestRejectsNonOriginFormTargets`.
8. **Misleading provenance.** Go's build stamp counted untracked files, so every result looked dirty. `git_dirty` now means "tracked files differ from HEAD".
9. **From the synthetic session:** a script bug (the h2c-on-both-sides case had no h2c-accepting proxy, so all three runs errored; fixed and re-run); truncating the mock's live log files corrupted ground truth (checked = 0), so the mock is now restarted per run; and a capacity fit through saturated runs is meaningless (R² −0.16), so only unsaturated runs enter the fit.

## 6. The synthetic rig, and why it exists

### 6.1 What you asked for and what it can and cannot give

No cloud provider had been chosen, so the rig-dependent exit criteria were blocked. You asked me to finish Phase 0 by creating synthetic rigs and data. I did so, and I want to be exact about what that buys: **it validates the procedure, the tooling and the *shape* of the results; it cannot validate the numbers.** A shared, virtualised laptop is not a measurement environment, and the harness correctly says so in every `summary.json`.

### 6.2 What the `local` provider is (AMD-012)

`deploy/rig/providers/local.sh` implements the plan's provider hook (`up | down | status`) on one machine:

- Roles pinned to disjoint cores with `taskset`: generator 0-2, mock 3-4, gateway/null proxy 5-6 (of 8). No sudo or network namespaces were available, so loopback is used.
- A throw-away CA and server certificate (EC P-256, valid 2 days) for the TLS runs, kept in a gitignored state directory and deleted at teardown.
- **Verified teardown:** `down` kills everything, deletes the state directory, then *checks* that no `twmock/twnull/twload` process and no listener on the rig ports (9300, 9302-9309) remains, and exits non-zero otherwise. This is the local analogue of "no orphaned cloud resources". It ran at the end of every session, including one I killed mid-way with a timeout.

### 6.3 The session (`scripts/rig-local-session.sh`, run as `p0-synth-20261122`)

Follows `bench/RUNBOOK.md`:

1. **Pre-flight:** `twload timer`, noise canary (its baseline was captured here), strict self-check.
2. **Floor:** 3 loads (250, 500, 1000 req/s) × 5 runs × {direct to mock, through null proxy}, 64 events per response, 5 ms event gap, 3 s warm-up + 15 s window, **randomized order** (so slow drift does not bias one load), 30 runs.
3. **Capacity grid:** rate and events per response varied independently (events 16 and 256 at each rate), so `c_r` and `c_e` are separable (the earlier single-rate fit could not).
4. **Transport/TLS:** at 500 req/s: h1/h1, upstream h2c, TLS+h1, TLS+h2, h2c both sides, 3 runs each.
5. **Trace replay:** the synthetic bursty trace vs Poisson at the same mean rate.
6. Teardown with orphan check. Total 53 runs, about 0.75 h, $0.

The mock is restarted before every run so each run reads only its own ground truth.

### 6.4 The synthetic trace (and its limits)

`twtrace` writes a Markov-modulated Poisson process (rate multipliers 0.2, 1, 3, 9; mean dwell 15 s) with the BurstGPT header I *believe* the real file uses, and heavy-tailed token counts. It exercises replay, rescaling and burst handling. It is **not** BurstGPT, is gitignored and regenerated deterministically (`bench/data/README.md`).

## 7. Results (shape only: 0 of 53 runs valid)

Every run failed validity on dispatch-lag p99 > 200 µs; three direct runs at 1 000 req/s also exceeded 60 % generator CPU. Full tables: `bench/sessions/p0-synth-20261122/analysis.md`; raw runs: `bench/results/p0-synth-20261122-*`.

**Floor, per-event delay (merged histograms; µs; direct → through null proxy)**

| Load | p50 | p99 |
|---|---|---|
| 250 req/s | 71 → 213 | 279 → 647 |
| 500 req/s | 65 → 390 | 463 → 8 495 |
| 1 000 req/s | 62 → 8 983 | 4 971 → 36 575 |

The null proxy saturates at about 1.2 busy cores on its two pinned cores; the knee lies between 250 and 500 req/s at 64 events. Beyond it, latency is queueing.

**Capacity fit.** Using only unsaturated runs (SUT cores < 1.0; 8 runs over 3 rates × 2 event counts): `c_r ≈ 436 µs` CPU/request, `c_e ≈ 15.5 µs` CPU/event, R² = 0.996. The plan's hypothesis was `c_e ≈ 4 µs`. At 20 000 req/s × 64 events (1.28 M events/s) this predicts ≈ 28 busy cores for the null floor alone. The fit through *all* runs gives R² = −0.157 and is shown in `analysis.md` only as a warning.

**Transport/TLS at 500 req/s × 64 events (per-event delay p99, across-run mean ± 95 % CI)**

| Variant | p99 |
|---|---|
| h1 down / h1 up | 12.3 ± 4.3 ms |
| h1 down / h2c up | 7.0 ± 1.2 ms |
| TLS + h1 | 11.6 ± 0.6 ms |
| TLS + h2 | 12.5 ± 5.2 ms |
| h2c both sides | 56 ± 206 ms (merged p99 106 ms) |

**Burstiness.** Same 500 req/s mean: request p99 12.7 s with the bursty trace vs 0.63 s with Poisson. Arrival burstiness decides the tail more than the mean rate, which is why the real trace matters later.

**Ground-truth control.** 22 229 streams checked; 4 438 injected spans; **4 438 leaked** through the pass-through proxy; **0** benign streams altered; 0 parse errors. This is the control that gives a future "0 leaks" its meaning: the detector can find leaks when they exist.

## 11. How to reproduce

```
make build test                       # race tests (short)
make selfcheck-laptop                 # self-validation, timer checks relaxed
make bench-quick                      # 60 s single-box sanity run
make rig-local S=<name>               # full synthetic session (~20 min; don't run other heavy jobs)
make rig-local-analyze S=<name>       # bench/sessions/<name>/analysis.md
RIG_PROVIDER=local deploy/rig/rig.sh down   # verified teardown
```

Results: `bench/results/<run-id>/{env.json, summary.json, raw/*.hdr, raw/config.json}`. Runs from the synthetic session record the parent commit with `git_dirty=true` because the session tooling was committed together with the results.
